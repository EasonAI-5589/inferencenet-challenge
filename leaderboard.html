Study design and sources

Tasks and harnesses

The 100 development tasks are the development split of a pinned 100-task selection drawn from Selected_1000 (dataset revision 59f9512). Task IDs are not published. Each combination of a model and a harness has one recorded result for every task. New runs used DeepAgents 0.7.13, DeepSeek Harness (the official deepseek-harness-sdk 0.1.5rc1 in a restricted InferenceNet composition whose only tool is run_python), Claude Agent SDK 0.2.165 and OpenAI Agents SDK 0.23.1, and reached every model through an Anthropic Messages–compatible gateway.

Provenance, thinking and budgets

Results come from new runs, inherited SDK runs, historical DeepAgents runs and offline-derived DeepAgents metrics, and all keep their recorded metrics; the report summary gives the count of each. Harness versions are verified for new runs and, through per-run identity records, for 1,199 of the 1,200 inherited SDK runs; historical and offline-derived runs record none. New Claude Agent SDK runs set no thinking override, but the study’s run notes report that the bundled Claude CLI adds adaptive thinking at high effort; request records were not independently checked. New runs on the other three harnesses use the provider default with no override. Thinking for historical, offline-derived and inherited runs is not recorded. Recorded budget caps (6 model calls, 4 tool calls, 32,768 output tokens, 1,800 s wall time, 90 s per tool call) are stored with every new and inherited SDK run; they are the configured limits, not independent measurements of execution. Historical and offline-derived DeepAgents slots record no caps.

  • Full replication: coefficient and standard error within 1% relative error; p-value within 0.01 absolute error.
  • Coefficient and SE within 5%: coefficient and standard error both below 5% relative error.
  • Coefficient within 5%: coefficient relative error at most 5%.
  • Correct sign: estimate and reference are both positive or both negative.
  • Correct significance: correct sign and the same p-value band as the reference (p < 0.01, 0.01–0.05, 0.05–0.1, ≥ 0.1).

All five metrics use the local-paper-v1 scoring profile, and every score divides by all 100 tasks of its combination. Full replication uses the same rule as on the 1,000-task leaderboard, which scores its other four metrics with hf-leaderboard-v1.

Each task counts once, under one of four outcomes:

  • Scored: the run ended with a final result whose full-replication flag is recorded as true or false. For historical and offline-derived DeepAgents slots, the flags come from archived or offline-derived metrics rather than a new run.
  • Failed: the run definitely ended without a scorable result, for example from budget exhaustion, a missing or malformed final program, a final execution failure, or an SDK or worker error. Local queue failures and HTTP 402 billing rejections are attributed to infrastructure. No failure is attributed to model capability; the rest stay unattributed.
  • Unknown: the run was sealed, but its outcome could not be established. Causes include study interruptions, transport or provider errors, rate limits, access rejections, task deadlines and a content-policy rejection; some remain unattributed. Unknown runs are never counted as failed or false.
  • Pending: planned but not yet sealed; none in v10.

All four stay in each 100-task denominator; only successes add to a score. Only scored runs carry metric flags. A flag is also missing when the reference is unsupported, and 236 historical scored results recorded Full replication only, so each metric reports its own count of unknown or missing results.

How the numbers were checked. Counts and metric values are recomputed from the per-task records embedded in the v10 report. Result receipts were checked for 5,182 of the 5,600 task results (every new and inherited SDK run): each file is present with a matching hash, and its lifecycle state, reason and recorded caps agree with the report. The 418 historical and offline-derived results have no receipts. Receipts contain no metric flags, so metric values are taken from the report and were not re-scored. Some facts, such as the Claude CLI’s thinking behaviour, come only from the study’s run notes.

This is a descriptive development comparison. The two boards differ in task count, in the scoring profile of four metrics, and in provenance and settings, so they are not directly comparable. Within this study, cells mix new runs with older results recorded under other settings, so differences between cells are not equal-cost comparisons and do not establish causes. Equal recorded caps do not mean equal reasoning compute. Cost and running time are not reported.

03 / Research

Research directions

Our goal is to understand how models and harnesses can improve econometric replication, and turn evaluation evidence into better systems and training signals.

  1. 01

    Model–Harness Coupling

    Study how different models and harness architectures work together, and which combinations improve replication performance.

    Harness: what it is, three taken apart →

  2. 02

    Self-Evolving Harnesses

    Explore a feedback-driven cycle of automatic harness design, evaluation and refinement, using execution trajectories and replication outcomes to guide each update.

    See our ModularRSI-style development study →

  3. 03

    Trajectory-Based Post-Training

    Investigate how validated agent trajectories, tool feedback and replication outcomes can support model post-training, including trajectory distillation and reinforcement learning.

Evaluation protocol and sources

Model

One code-generation call, followed by execution. No iterative tool or feedback loop.

Model + Harness

The current results use DeepAgents, with up to six model calls and four trial tool executions. The final program is replayed and scored.

Published result archives: Hugging Face PR #4.

  • Full replication: coefficient and standard error within 1% relative error; p-value within 0.01 absolute error.
  • Partial replication: target coefficient within 5% relative error.
  • Execution success: code executes successfully under the archived scoring profile.
  • Coefficient direction: estimated and reference coefficients have the same sign.
  • Significance level: estimated and reference p-values fall in the same significance band.

Full replication comes from the published evaluation summaries (local-paper-v1). The other four metrics come from archived per-task scores (hf-leaderboard-v1). These scoring profiles have not been verified against the official scorer. Unknown and invalid outcomes remain in the 1,000-task denominator without earning successes.

The six models share Selected_1000 at dataset revision 59f9512. Execution environments, time limits and recovery protocols differ across historical batches. See the accepted archives for per-run settings and evidence status.
